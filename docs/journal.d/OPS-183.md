## What happened

`.claude/stridal.lock` pins a plugin release and one engine sha256 per platform, in a line format (`release <v>`, `engine <goos>/<goarch> <sha256>`) that the sh launcher reads with awk and `engine.Parse` reads in Go. Any line either reader does not know is an error. `template/.claude/hooks/stridal-engine.sh` is the bootstrap launcher (ADR-0018 decision 7). In a repository with no model marker it stands aside without reading the payload. Otherwise it reads the lock through git from `refs/remotes/origin/<main>`, or from `refs/heads/<main>` only when the repository has no origin, so a worktree is always guarded by main's pin. It verifies the plugin's engine for this platform against the pin and runs it on the control (`stridal hook <control>.sh`, which execs the shell control). On a missing or bad lock, no pin for the platform, a plugin that is not the pinned release, or an engine that is missing, mismatched or will not start (126, 127), it refuses with one fix line. In that state it still allows `git fetch`, the plugin update and `stridal doctor`. `STRIDAL_ENGINE` counts only under a fixture HOME. `internal/engine` is the Go twin, and doctor's new engine line reports what the launcher would decide here.

There are 28 launcher cases, a 30-command recovery corpus and a 14-text lock corpus, each run against the real launcher in a fixture. Each case is also checked against `engine.Decide`. `TestEachLauncherCaseFailsWithoutItsControl` replaces one control at a time across 37 mutants and requires every case it names to fail. Every non-corpus case is named by at least one mutant. Two corpus entries were first shown to pass without the character filter, because the fetch-flag rule caught them, and were rewritten so that each tests the filter alone.

## Decisions

- **The launcher is not registered.** No release carries an engine until OPS-184, and a marked repository with no engine refuses every guarded call. Registering it now would refuse every Bash call here and in every `/stridal:init` repository. OPS-184's row now registers it on both paths, with `onFailure: "block"` and a timeout, and turns doctor's note into a FAIL then.
- **Resolve once (SessionStart writing `CLAUDE_ENV_FILE`) is not built.** It rests on an open OPS-199 spike. Each call reads the lock with git and hashes the engine.
- **The recovery allowlist lives in the launcher**, because it must run when no engine can be trusted: an unverified binary is never exec'd. `engine.IsRecovery` is its twin, and the corpus holds the two equal. It matches only whole commands made of plain characters, and `git fetch` accepts only listed flags, so neither `--upload-pack` nor `-c` gets through.
- **Where the engine lives** (`<plugin root>/engine/<goos>-<goarch>/stridal`, or the root plugin-session.sh records, for the copy install) is OPS-184's to settle once OPS-199 has found where binaries can live.

## Surprises

The latency measured in the sandbox is about 120 ms per call over a bare control. Almost all of it is the cost of starting a process under Seatbelt: a bare `sh` control alone takes 10 ms there, and the launcher starts about 13 processes. Through `/usr/bin/git`, the sandbox also adds about 100 ms per git call, because xcrun cannot write its cache. ADR-0018's 10 ms ceiling needs resolve-once and one dispatcher per event (OPS-185). On the Mac outside the sandbox: `go -C framework test -count=1 -run TestLauncherLatency -v ./internal/engine/`.
